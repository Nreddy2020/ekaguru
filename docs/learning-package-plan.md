# From notes to a learning package: mapping the owner's framework (12 September 2026)

The owner set out a framework for notes that are built, not summarised: know the audience first,
understand the whole book before writing, write in layers (simple, concept, example, visual,
practical, advanced), keep one chapter structure, progress by difficulty, change the approach
entirely for children, produce a teacher edition and a professor edition, make IT material
practical, generate revision formats from the same source, connect every concept to its example,
mistake, question and revision, keep a concept dependency map, offer "explain it like I am…" at
every level, and deliver a master learning package per book. This document says what of that Guru
already does, what is missing, and the order to build the rest.

## What exists today (Guru Notes, blueprint notes-v3)

| Framework element | Status | Where |
| --- | --- | --- |
| Audience: school child, with the parent following | done for one audience | notes prompt writes to the child as "you"; the class level comes from the book |
| Understand the source before writing | per page, not per book | page reading (vision plus OCR), block coverage rules, source review |
| Layer 1 simple, 2 concept, 3 example, 4 visual, 5 practical | done per topic | explanation paragraphs, everyday example, page crop and Guru drawing, try-it-now activity |
| Layer 6 advanced (why, alternatives, limits, internals) | missing | needs the audience switch below |
| Consistent chapter structure (definition, why, terms, how, example, points, mistakes, questions) | done per topic | heading, explanation, words to know, example, tip, doubts, check-yourself |
| Difficulty progression | partly | lessons have five depths; notes have one level per page |
| Children's approach (story, pictures, activities, revision) | done | overview story, book pictures, drawings, activities, summary |
| Teacher edition (objective, prerequisites, board plan, activity, questions, misconceptions, assessment, homework, answer key) | partly | lessons carry board plans, rubrics and misconceptions; not assembled as a teacher edition |
| Professor and IT editions | missing | needs audience-aware blueprints and non-school book intake |
| Revision formats (full, quick, memory, one page, question bank, answer key, cards, viva) | derived from the notes on the board (this stage) | see below |
| Connected notes (concept, example, mistake, question, revision) | done per topic; not across pages | topic sections; no cross-page links yet |
| Concept dependency map | missing | needs a book-level pass |
| "Explain it like I am…" ladder | missing at reading time; the depth ladder exists for lessons | one explanation per topic today; readers' questions extend it |
| Master learning package per book | missing | whole-book preparation exists; no package view |

## Order of work

Each step builds on the previous one and is testable on the EVS Class 5 book already prepared.

1. **Revision layer from existing notes** (this stage, no model calls). From a page's notes derive:
   quick notes (objectives, one line per topic, summary), memory notes (words to know, tips,
   must-remember points), flash cards (term to meaning, question to answer, readers' questions),
   a question bank by difficulty (check-yourself easy, doubts medium, readers' questions
   extended) with answers, and a one-page sheet. Shown as the board's resource tabs in notes
   mode; the print article prints the full notes.
2. **Book knowledge map.** One pass over a prepared book: chapters from page titles and headings,
   topics per page, key terms, and a concept dependency map ("to understand X you need Y", by
   page). One model call per chapter over the notes' headings and terms, validated against the
   pages. Shown in the library as the book's roadmap and used to say, when a child struggles with a
   topic, which later pages will be affected and which earlier page to revisit.
3. **Cross-page links.** Each topic gains "builds on" and "leads to" links from the map, and the
   "Guru remembers" line uses them for recaps.
4. **"Explain it like I am…" ladder.** For any topic, a second and third explanation on request
   (younger, same age with another analogy, older or expert), generated once and saved with the
   notes like readers' questions, so the ladder grows and costs nothing after the first ask.
5. **Teacher and parent edition.** For a page: objective, prerequisites, how to explain it at
   home or on the board (board plan from the lesson), the activity, questions to ask, common
   misconceptions, a short assessment with an answer key, homework. Assembled from the lesson
   plan and the notes; one extra model call for the parts that do not exist yet.
6. **Audience editions for uploaded books.** An audience setting at upload (child, school
   student, college student, teacher, professor, IT professional, manager, competitive exam)
   selects the blueprint: the children's blueprint is the current one; the professional blueprint
   adds the problem-solved, architecture, implementation, commands, troubleshooting, scenarios,
   labs and interview questions structure; the professor blueprint adds foundations, research
   perspective, case studies, limitations and references. Validators per blueprint; the same
   coverage and no-copying rules for all.
7. **Master learning package.** One view per book that assembles the roadmap, chapter notes,
   concept map, examples, mistakes, memory tricks, exercises, question bank, answer key, mock
   test, revision notes and one-page sheets, printable as one document.

Steps 1 to 3 need no new provider capacity beyond what the whole-book preparation already uses.
Steps 4 to 7 add one or two model calls per page or chapter, once, shared by everyone.
